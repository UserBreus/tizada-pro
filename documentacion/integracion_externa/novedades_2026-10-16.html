El acomodo de las piezas mejoró: gasta entre 1 y 2,5 % menos de tela en todo lo que medimos (ver sección 6). Le llega igual a los pedidos que vienen de su sistema.

1
Lo que hace el operario en el paso Arte

Ajustar el diseño por la API

Todo va dentro de cada variable del diseño: disenos[].moldes[]. Los nombres de objeto son los de las capas «Editable …» del arte (sin la palabra «Editable»).

ajustes: mover, rotar, escalar, espejar

ClaveQué es
dx, dyCorrimiento en fracción del ancho / alto del diseño. +dx derecha, +dy abajo. 0.05 = 5 %
rotGiro en grados
scale o sx / syEscala (1 = igual). Negativo = espejo en ese eje
tallesOpcional: sólo en esos talles. Sin él, en todos

colores: el color de un objeto

fill (relleno) y stroke (borde), cada uno [C, M, Y, K] con valores de 0 a 1.

mapeo_arte: qué mesa del arte va en cada pieza

Sólo hace falta cuando la guía del arte no trae el nombre de la pieza. La pieza por su nombre (genérico o exacto); la mesa por su número (1, 2…) o el rótulo escrito en ella. Manda sobre lo automático.

Tipografías

reemplazos: una tipografía del arte por otra del catálogo. tipografia_por_campo: la tipografía de un campo (nombre, número…) sólo para este molde, pisa la del diseño. Los nombres válidos salen de GET /tipografias (o se mandan los archivos en tipografias).

"moldes": [{
  "variable": "v_redondo",
  "ajustes":  { "escudo": { "dx": 0.05, "dy": -0.02, "rot": 15, "scale": 1.2, "talles": ["M", "L"] } },
  "colores":  { "escudo": { "fill": [0, 1, 1, 0], "stroke": [0, 0, 0, 1] } },
  "mapeo_arte": { "Frente": 1, "Espalda": "ESPALDA" },
  "reemplazos": { "FuenteDelArte": "Anton Regular" },
  "tipografia_por_campo": { "numero": "Anton Regular" },
  "editables": { "sponsor": "no_imprimir" }
}]
"no_imprimir" en editables

El objeto no sale ni sublimado ni con la cruz de marca de proceso. Es el «Sin marca» de la pantalla.

2
Planilla y opciones

Reposición y perfil de color

planilla[].piezas: Repo (reposición)

Para rehacer sólo algunas piezas de una prenda (por ejemplo una manga que salió mal). Va en la fila, agrupado por variable o molde. Un nombre genérico («Manga») vale por todas las suyas. Sin piezas, la fila hace todas, como siempre.

"planilla": [
  { "talle": "L", "nombre": "PÉREZ", "numero": "10",
    "piezas": { "v_redondo": ["Cuello", "Manga 1"] } }
]
Ojo

Si la planilla de ese molde tiene la Repo apagada en la configuración, la fila con piezas frena con repo-no-admitido: hay que mandarla sin piezas.

GET /perfiles + opciones.perfil_color

Herramienta nueva: GET /perfiles devuelve los perfiles de color que tiene TIZADA: {"perfiles": [{"archivo", "nombre", "espacio"}]}. En opciones.perfil_color se puede mandar el archivo o el nombre de uno de esos. Uno que no existe frena con perfil-desconocido. Sin él, se usa el del sistema.

"opciones": { "perfil_color": "U.S. Web Coated (SWOP) v2" }
3
Cómo se arman las mesas

Largo de mesa, diseños y talles

mesas.largo_max_m: el largo máximo de cada mesa

En metros, de 0,10 a 50 (por ejemplo 12.5). Ninguna mesa del pedido pasa ese largo: lo que no entra sigue en otra mesa. Sin él rige el largo del nesting del molde (largo_mesa_cm de GET /variables). Vale con cualquier modo. Mal mandado → largo-mesa-invalido. Es el botón «Largo» de la planilla.

mesas.separar_disenos

Por defecto, el mismo molde se mezcla aunque cambie el diseño (camisetas JUGADOR y GOLERO van juntas para gastar menos tela). Con true, cada diseño va en sus propias mesas en cualquier modo, y cada archivo del resultado dice su diseno. Otro tipo de valor → mesas-invalido. Es el botón «Separar».

mesas.modo: "talles_separados"

Todos en la misma mesa pero sin mezclar talles: cada talle acomodado solo y apilado debajo del anterior, con una línea punteada y el rótulo de los talles entre medio. grupos es opcional (esos talles sí van mezclados). El resultado trae "separados": true.

mesas.modo: "una_por_fila" (Copia), cómo quedó

Mesa llena que se repite

Las copias de una fila se acomodan en una mesa del largo máximo. Si alcanzan para llenarla, sale UN archivo que se imprime copias veces (19 copias con lugar para 5 por mesa → 5 × 3, y el resto aparte).

El resto, junto

Todo lo que no llena una mesa, de cualquier fila y talle, se acomoda junto como en normal y se imprime 1 vez. Ya no se separa por talle (eso es sólo por_talles / talles_separados).

"mesas": { "modo": "normal", "largo_max_m": 10, "separar_disenos": false }

GET /a_medida/calcular acepta largo_max_m

Para banderas y piezas a medida: las cuentas («¿entra en la tela?», cuánto mide) se hacen con ese largo de mesa, el mismo que después va en mesas.largo_max_m.

Lo que contesta

Cambios en el resultado

En archivos[] del resultado (las tizadas), además de lo de siempre:

CampoQué dice
ancho_cmEl ancho imprimible de la tela (la mesa nunca se achica)
copiasCon una_por_fila: cuántas veces se imprime ese archivo
por_mesaCuántas unidades trae cada mesa. Unidades = por_mesa × copias

separadosCon talles_separados: true, y los cortes entre talles

Todas frenan el pedido (no se fabrica a medias). La lista completa y actualizada: GET /alarmas.

Un pedido con todo

Ejemplo completo

Un pedido de camisetas con dos diseños, un escudo corrido y de otro color, el sponsor sin imprimir, una reposición, perfil de color y mesas de 10 m.

{
  "formato": "tizadapro.pedido/1",
  "referencia": "SOL-2045",
  "disenos": [
    { "nombre": "JUGADOR",
      "moldes": [{ "variable": "v_redondo", "arte": "artes/jugador.ai", "tela": "232",
        "ajustes":   { "escudo": { "dx": 0.03, "scale": 1.1 } },
        "colores":   { "escudo": { "fill": [0, 0, 0, 1] } },
        "editables": { "sponsor": "no_imprimir" } }] },
    { "nombre": "GOLERO",
      "moldes": [{ "variable": "v_redondo", "arte": "artes/golero.ai", "tela": "232" }] }
  ],
  "planilla": [
    { "diseno": "JUGADOR", "talle": "L", "nombre": "PÉREZ", "numero": "10" },
    { "diseno": "JUGADOR", "talle": "M", "nombre": "GÓMEZ", "numero": "7",
      "piezas": { "v_redondo": ["Manga"] } },          // reposición: sólo las mangas
    { "diseno": "GOLERO", "talle": "XL", "nombre": "DÍAZ", "numero": "1" }
  ],
  "opciones": { "perfil_color": "U.S. Web Coated (SWOP) v2" },
  "mesas":    { "modo": "normal", "largo_max_m": 10, "separar_disenos": false }
}

Los nombres exactos de cada campo (variable, columnas de la planilla, arte) son los de FORMATO_PEDIDO.md; este ejemplo muestra dónde va cada cosa nueva. Antes de mandarlo, POST /pedidos/validar dice si algo frena, sin fabricar nada.

6
Sin cambiar nada de su lado

Lo que mejoró solo

Los pedidos que llegan de su sistema se arman con el mismo motor que la pantalla, así que reciben estas mejoras sin mandar nada distinto.

Acomodo más preciso

Cada pieza queda a la distancia exacta de sus vecinas, medida con su contorno real (rectas, curvas, puntas). Antes quedaban 5-6 mm de más en cada contacto.

Busca el mejor orden

Prueba muchas formas de ordenar las piezas a la vez (usa todos los núcleos de la PC) y se queda con la que gasta menos tela. Las chicas se meten en los huecos de las grandes.

Menos tela

Medido: 20 camisetas 14,90 → 14,72 m; 689 banderines 35,29 → 34,42 m; 40 mangas 3,42 → 3,23 m.

Siempre igual

El mismo pedido con la misma configuración da la misma tizada, pieza por pieza, en cualquier PC. Cambia sólo si cambia algo del pedido o de la tela.

El mismo molde se mezcla

Distintos diseños del mismo molde comparten mesa para gastar menos (salvo separar_disenos).

Marcas de tiras más visibles

En banderas y piezas a medida, las marcas de las tiras salen negras con contorno blanco.

Tiempos

Un pedido de unas 100 piezas tarda alrededor de 15 s en acomodarse; con más de 120 piezas por acomodo (Copia grande, cientos de banderines) se acomoda como antes, en pocos segundos. Conviene que su sistema espere el resultado por el aviso (webhook) o consultando GET /pedidos/{referencia}, sin un tiempo fijo.
